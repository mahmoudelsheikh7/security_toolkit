Harden a Linux machine with one command

Security Toolkit installs common security tools, scans folders for suspicious files, and sets safe firewall defaults. It is a single C++17 program with no dependencies, and it works on Debian, Fedora, Arch, openSUSE, Alpine and Void families.

Download and build

You need a C++17 compiler (GCC 8+ or Clang 7+) and make. On Debian/Ubuntu install them with sudo apt install g++ make git; on Fedora sudo dnf install gcc-c++ make git; on Arch sudo pacman -S gcc make git.

git clone https://github.com/mahmoudelsheikh7/security_toolkit.git
cd security_toolkit
make
sudo make install   # optional: installs to /usr/local/sbin

No make? Compile directly: g++ -std=c++17 -O2 security_toolkit.cpp -o security_toolkit. On GCC 8, add -lstdc++fs.

What it does

Install tools

Detects your package manager and installs nmap, fail2ban, rkhunter, lynis, clamav, tcpdump and friends one by one, so one missing package never blocks the rest.

Scan files

Walks a folder and flags hidden files, executables, setuid/setgid files, world-writable files and risky extensions such as .sh, .so and .ko. Symlinks are not followed.

Set up the firewall

Uses ufw or firewalld: deny incoming, allow outgoing, and keep your SSH port open so you cannot lock yourself out.

Usage

sudo ./security_toolkit                 # interactive menu
sudo ./security_toolkit --install       # install security tools
./security_toolkit --scan /home         # scan a folder (no root needed)
sudo ./security_toolkit --firewall      # apply firewall defaults
sudo ./security_toolkit --all /var      # install, scan, firewall
./security_toolkit --help

Add --yes to skip confirmation prompts, for example in scripts. Add --no-color for plain output. The log is written to /var/log/sec_toolkit.log, or to ~/.local/state/sec_toolkit/ when you are not root.

Safety features

  • Reads every SSH port from sshd_config and your current session, and keeps them all open.
  • Never deletes your existing ufw rules, and asks before changing the firewall.
  • Runs commands without a shell, so file names and input cannot inject commands.
  • Skips /proc, /sys and /dev when scanning, and keeps going past unreadable folders.

Test on a non-production machine first, especially the firewall step on remote servers. The scanner reports heuristics; it is not an antivirus and cannot prove a file is malicious.

If a package fails to install

SystemFix
RHEL, Rocky, AlmaEnable EPEL: sudo dnf install epel-release. fail2ban, lynis and clamav are there.
ArchRun sudo pacman -Syu if you see 404 errors. Some tools may only exist in the AUR.
openSUSElynis and rkhunter can require the security:tools or Packman repositories.
AlpineEnable the community repository in /etc/apk/repositories.
